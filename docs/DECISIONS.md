# 설계 결정 기록

## 1. 이미지 생성: Canva → HTML 템플릿 + Playwright

처음엔 Canva 브랜드 템플릿 연동을 검토했으나 두 가지 이유로 접었습니다.

**요금제** — Canva Connect 의 Autofill API(`POST /v1/autofills`)는 공식 문서상
**Canva Enterprise 조직 구성원**을 대신해서만 호출할 수 있습니다.
Pro/Teams 로는 템플릿의 데이터 필드를 **조회**할 수는 있어도(`GET /v1/brand-templates/{id}/dataset`)
실제로 **채워 넣을 수는 없습니다**.

**인증** — Canva 의 refresh token 은 **1회용**입니다. 갱신할 때마다 새 토큰이 나오고 이전 것은 폐기됩니다.
같은 토큰을 두 번 쓰면 `Refresh token used twice. All access tokens granted from this flow are now revoked.`
와 함께 해당 인증 흐름의 모든 토큰이 즉시 전면 폐기됩니다.
GitHub Actions 러너는 상태를 저장하지 않으므로 매번 새 토큰을 어딘가에 되써야 하고,
작업이 중간에 실패하거나 두 실행이 겹치면 수동 재인증이 필요해집니다.
무인 자동화의 목적 자체가 무너집니다.

**대신 택한 방식** — HTML+CSS 를 Playwright 로 스크린샷.
인증도 요금제도 없고, 템플릿이 저장소에서 git 으로 버전 관리됩니다.
그리고 이 프로젝트의 요구사항이었던 "항상 동일한 글씨체와 위치"에
CSS 쪽이 오히려 더 정확합니다 — 값이 코드에 박혀 있으니까요.

Pillow 직접 렌더링도 후보였지만 제외했습니다.
`ImageDraw.text()` 는 자동 줄바꿈이 없고, 한국어는 공백 없이도 줄을 나눠야 해서
어절 단위 폭 계산을 직접 구현해야 합니다. 텍스트 길이가 매일 달라지는 용도에는 부담이 큽니다.
CSS 는 `word-break: keep-all` 한 줄로 해결됩니다.

## 2. 인스타그램 로그인 경로: Facebook Login 권장

Instagram Login 은 페이스북 페이지가 필요 없어 초기 설정이 간단하지만,
장기 토큰이 **60일**이라 주기적 갱신이 필수입니다. 갱신을 놓치면 자동화가 통째로 멈춥니다.

Facebook Login 으로 얻는 **페이지 액세스 토큰은 만료되지 않습니다**.
페이지를 하나 만드는 수고를 한 번 들이면 이후 토큰 관리가 사라집니다.

두 경로 모두 코드에서 지원하며 `IG_LOGIN_MODE` 로 전환합니다.
Instagram Login 을 쓸 경우를 대비해 `refresh-token.yml` 워크플로도 넣어 두었습니다.

## 3. 이미지 호스팅: GitHub Pages

인스타그램 Content Publishing API 는 이미지를 URL 로만 받습니다.
메타 서버가 직접 그 URL 을 내려받으므로 **공개 접근 가능한 HTTPS 직접 링크**여야 합니다.

별도 스토리지(S3/R2)를 쓰지 않고 `gh-pages` 브랜치 + GitHub Pages 를 쓴 이유는
추가 계정·비용·자격증명이 없고, 저장소 안에서 발행 이력이 함께 남기 때문입니다.

Pages 배포에 수십 초가 걸리므로 게시 전 `scripts/wait_for_pages.py` 로
실제 공개 여부를 확인합니다. 이 대기가 없으면 `9004 / 2207052`(이미지 다운로드 실패)가 납니다.

## 4. 출력 포맷: PNG 가 아니라 JPEG

메타 공식 문서는 **JPEG 만** 지원한다고 명시합니다.
실무에서 PNG 가 통과한다는 보고가 있지만 보장되지 않으므로,
렌더 후 Pillow 로 sRGB JPEG 변환하고 8MB 미만인지 확인합니다.

## 5. 게시 한도를 하드코딩하지 않음

24시간 게시 한도가 메타 문서 안에서도 50과 100으로 엇갈립니다.
숫자를 박아두는 대신 `GET /{ig-user-id}/content_publishing_limit` 로 실시간 조회합니다.

## 6. 공공데이터포털 API 의 함정 처리

`src/common/http.py` 한 곳에서 흡수합니다.

- `dataType=JSON` 을 줘도 **게이트웨이 레벨 오류는 XML** 로 옵니다 → 응답 첫 글자로 판별
- 인증키는 **Decoding 키를 params dict 로** 넘깁니다 (URL 에 직접 붙이면 이중 인코딩)
- `numOfRows` 기본값이 **10** 이라 조용히 잘립니다 → 항상 명시
- 값이 전부 문자열이고 결측이 `'-'`, `null`, `''` 로 옵니다 → `to_float` / `to_int` 로 방어
- 응답 지연이 잦습니다 → 타임아웃 20초 + 지수 백오프 3회 재시도
- 키/권한 오류(30, 31, 32, 20, 12, 22)는 재시도해도 소용없으므로 즉시 중단

## 7. 실거래가 집계에서 제외하는 것

`cdealType == "O"` 인 **해제된 거래(계약 취소)** 는 평균가 계산에서 뺍니다.
넣으면 이미 취소된 신고가가 평균을 왜곡합니다.

또한 실거래 신고 기한이 계약 후 30일이라 **최근 월 데이터는 계속 갱신**됩니다.
월초에 실행하면 표본이 너무 적으므로, 거래가 10건 미만이면 직전 달로 자동 후퇴합니다.
